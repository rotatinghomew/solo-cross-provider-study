# 家校协作项目的证据综合与续资助

数据来自独立设计的合成业务记录，不含真实人员资料。文件为 UTF-8 JSON。

## 资料字典

`estimates` 的一行是一个研究在一个随访窗口、一个组别的汇总；未观测的人不等于回答否。`assigned` 指该研究按 `denominator` 确定的基数。多个研究的 `cohort` 相同意味着关联线索，不代表两批完全相同；`overlap` 给已核实的共享对象数区间及是否跨窗口、跨组，`valid_on` 相同配对以截至日最新版本为准。未声明独立不等同相关性为零；在仅有汇总而无法确认共变结构时应按可辩护的不确定范围说明可证程度。`registration` 的效应下界用邀请与对照之间下一步完成比例之差；比较按共同的周数进行，不能跨周合并成一次观察。`costs` 的运行费用逐站点计，共同采购同一供应方的固定费用只收一次；`decisions` 的已签资金和支出状态是实际约定，不随综合估计重写。
`paired` 每个表是有关研究在同一周数的已共同观察对象，`yy`、`yn`、`ny`、`nn` 分别表示两边完成、仅左、仅右、两边均未完成。表给的是已共同查到的部分，不能自动外推到未观察的重叠家庭。用登记表的研究、组与原招募范围复核配对。`trial_pools` 是可供同组试办的招募及对照总量，`trial_options` 是站点在该池的需求；同池不能把名额拿给两个站点各用一次。`basis` 相同的两项试办即使重复招募时段不同，也不能独立证明该证据缺口得到两份证实。各池的成本开支仍按 `costs` 办理。

## 读取与核对

使用 Python 3.11。
本地虚拟环境可按 `python3 -m pip install -r requirements.txt` 安装锁定的数值工具。有隔离运行环境时可直接使用已安装版本。

用 `python3 -m json.tool data/records.json` 查看原始记录。用 `python3 -m unittest discover -s tests -v` 核对演练资料的格式及关联。仓库目前只提供资料与输入核对，不提供业务分析结果。
